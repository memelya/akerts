GEN UI мониторинг + GigaCode CLI

Скачать актуальный архив с GitHub:
https://github.com/memelya/akerts/raw/refs/heads/gh-pages/downloads/genui-gigacode.zip

НА РАБОЧЕМ НОУТБУКЕ
1. Нужен Python 3.10+, установленная GigaCode CLI и рабочая авторизация CLI.
   Пользователь указал GigaCode v26.8.60. Флаги проверяются по --help
   установленной версии, а не по предположению о версии.
2. Убедитесь, что gigacode запускается в вашем терминале и отвечает на запрос.
3. Распакуйте проект в отдельную папку. Запустите START_GIGACODE.cmd.
   При первом запуске configure_gigacode.py находит CLI и проверяет --help.
   Он записывает только команду вызова в .local-data/ai-config.json.
   Ключи и токены проекта не нужны: используется авторизация самой CLI.
4. Обработка Авто вызывает модель для исследований и мониторинга;
   GigaCode CLI вызывает модель для каждого запроса. Подробнее README-AI.txt.
   Откройте адрес из окна сервера. Обычно http://127.0.0.1:8015/genui/.
   Выберите «GigaCode CLI». Источник — только ваши CSV в папке date.
5. Свои данные: date/push-sms.csv и date/success-screen.csv.
   При первом запуске CSV содержат только заголовки, показатели пустые.
   Справочники прошлой версии сохранены в .local-data/reference.json.
   Запрос и кнопка «Проверить данные» перечитывают CSV.

Если gigacode не найдена в PATH:
  python configure_gigacode.py --executable "C:/path/to/gigacode.exe"
Для npm установки с Windows .cmd скрипт ищет JS entrypoint и вызывает
Node напрямую. Если это не удалось, укажите путь самостоятельно:
  python configure_gigacode.py --node-entry "C:/path/to/gigacode.js"
Запускайте CLI без интерактивного меню: один запрос, один ответ, завершение.
Настройка проверяет --prompt и --approval-mode plan. При наличии
--output-format text использует текстовый вывод. Если --help вашей сборки
отличается, настройка остановится с объяснением; пришлите её вывод.

ПРИМЕРЫ
Покажи отправки, ответы и CSI опроса 193 на одном графике за последние 3 месяца.
Добавь CSI и объедини на одном графике.
Теперь покажи показатели отдельно.
Сравни с опросом 1007 на одном графике.

ДИАЛОГ
Сообщение пользователя и график ответа появляются в общей ленте.
Следующее сообщение создаёт следующий график ниже. Предыдущие сохраняются.
Подсказки под ответом продолжают именно этот результат, даже если он не последний.
«Изменить этот график» включает обновление выбранного графика на месте.
Внизу остаётся сообщение с подтверждением изменения и ссылкой к графику.
«Без контекста» — отдельный вопрос. «Новый диалог» — очистка текущей ленты.
История хранится в текущей вкладке до обновления страницы.

Шкала слева — количество событий/отправок/ответов, справа — CSI от 1 до 5.
Легенда позволяет отключать линии, чтобы видеть малые значения крупнее.
Когда остаётся только CSI, шкала 1–5 переносится влево.
Нули не подставляются вместо отсутствующих наблюдений. CSI не суммируется.

ПОЯСНЕНИЯ НОВОЙ ВИЗУАЛИЗАЦИИ
Пояснения проверяются отдельно от исполняемого кода: заголовок до 140 символов,
описание и обоснование до 4000 символов каждое; действия и ограничения — до
12 пунктов по 600 символов. Общий предел пояснений — 16000 символов.
Текст показывается как обычный текст, в том числе упоминания HTML и знаки сравнения.
При ошибке только в пояснениях модель исправляет пять текстовых полей отдельным
вызовом; HTML, CSS, JavaScript, ссылки и рассчитанные значения сохраняются.
Повторная ошибка относится в журнале к проверке результата, а не ожиданию модели.
Можно повторить создание интерфейса по уже подтверждённым данным, пока доступен
бюджет вызовов. Лимиты кода, изоляция и обязательный предпросмотр сохраняются.

РЕЙТИНГИ
Запрос «Покажи топ 10 опросов по отправкам за 2026 год» создаёт рейтинг,
а не фильтр приоритета Топ. Поддерживаются отправки, ответы, события, CSI и отсечения.
SQLite считает значения по всем строкам выбранного периода и всем опросам отбора.
Лидеры выбираются по убыванию, затем формируется интерфейс. Каталог модели и первые
строки CSV не ограничивают расчёт. При равных значениях порядок: канал, номер опроса.
Одинаковый ID в разных каналах — отдельные участники с явной подписью канала.
Нулевые значения участвуют, неизвестные исключаются. Для CSI рейтинг учитывает
только валидные оценки с весом событий. Низкая выборка требует отдельной проверки.
Фильтры продукта и приоритета можно добавить явно: «топ 10 ... с приоритетом Топ».
В подтверждении видны весь охват, число исходных строк и число участников результата.
При месячном рейтинге исходные дневные строки агрегируются в SQLite по месяцам,
статусам и оценкам. Лимит чтения исходных строк не обрезает список кандидатов.

КАК ЭТО РАБОТАЕТ
Браузер -> POST /api/genui -> установленная GigaCode CLI -> JSON параметров
-> локальная проверка -> расчёт по CSV -> график.
CLI получает пользовательский текст, прежние параметры, список ID и
релевантные названия опросов. Числовые значения CSV в запрос не включаются.
Сетевая работа CLI зависит от её корпоративной/облачной конфигурации.
Процесс запускается без shell в отдельной временной папке, с plan режимом,
ожиданием планирования до 120 секунд и генерации нового интерфейса до 240 секунд.
Оба лимита можно настроить до 300 секунд: planningTimeoutSeconds и codeTimeoutSeconds.
Старые настройки timeoutSeconds сохраняются для совместимости; без новых полей
планирование использует 120 секунд, создание кода — 240 секунд.
Перед созданием интерфейса можно выбрать 120, 240 или 300 секунд.
Во время вызова видны прошедшее время и лимит; кнопка остановки завершает процесс CLI.
После таймаута доступен отдельный повтор только генерации кода: подтверждённый
план и рассчитанные значения не меняются, модель заново не выбирает данные.
Повторы ограничены общим бюджетом вызовов. Если CSV изменились, требуется новый запрос.
Таймаут не означает ошибку авторизации. В журнале ожидание кода, проверка структуры
и предпросмотр в браузере записываются отдельно.
Расчёты выполняет локальный сервер. Новый код интерфейса запускается только
в изолированном предпросмотре, затем применяется пользователем.
При совпадении ID в каналах проверяются строки за выбранный период, включая нули.
Если наблюдения есть только в одном канале, он выбирается автоматически; если в обоих —
выберите «Пуш + СМС» или «Экран успеха». Значения разных каналов не объединяются неявно.
При ошибке CLI интерфейс показывает ошибку. Скрытой подмены модельного ответа
локальным разбором нет. «Локальный разбор» можно явно выбрать вручную.

РУЧНАЯ НАСТРОЙКА
ai-config.example.json — образец для .local-data/ai-config.json.
command: список программы и аргументов, полный путь допустим.
input: argument с {prompt}; stdin без placeholder; file с {prompt_file}.
responsePath: пусто для JSON спецификации или путь к строковому полю JSON
оболочки (например response). Для stdout с логами нужен тихий режим CLI.
При смене настроек перезапуск сервера не нужен: файл читается при запросе.
Файл настроек не раздаётся браузеру и не включается в архив.

Ответ модели:
{"ids":[193],"metrics":["sends","answers","csi"],"monthsCount":3,"layout":"combined"}
Уточняющий вопрос: {"clarification":"Какой опрос показать?"}

Проверка наличия настройки: GET /api/genui/status (без вызова модели).
Запуск без CLI: START_LOCAL.cmd. Не закрывайте сервер во время работы.
После перезагрузки ноутбука запустите соответствующий .cmd снова.
