АДМИНКА СТАТУСОВ status_det · 2026.11.18.2

Где: Администрирование → Статусы (адрес /genui/#admin-statuses, коротко #statuses).
Что даёт: группы и коды status_det с понятными названиями, цветом, порядком и
алиасами; эти настройки сразу используются в воронке диалога (шаги отсечений,
drill-down до кодов) и в разбивке событий по группам.

ПЛАН (как промт адаптирован к проекту)
 Промт предлагал NestJS/FastAPI + React + PostgreSQL + Redis. Проект — локальная
 установка без сторонних пакетов: Python 3.10+ (http.server), SQLite, чистый JS.
 Поэтому:
  - БД — SQLite-файл .local-data/status-admin.sqlite3 (отдельно от выгрузок:
    справочник переживает перезагрузку CSV и переносится вместе с папкой);
  - API — REST на том же локальном сервере (start_local.py), JSON, коды ответов
    HTTP как в промте;
  - кэш — в памяти процесса, TTL 5 минут, сброс при любом изменении (Redis для
    одного локального пользователя не нужен);
  - фронтенд — модуль genui/status-admin.js в стиле остальных разделов
    (перетаскивание — нативный HTML5 drag-and-drop + кнопки ↑↓ для клавиатуры);
  - роли — задаются на компьютере с сервером, браузер их не выбирает.
 Утверждённые показатели «Стоп-листы» (1002) и «Политика контактов» (список
 POLICY в metric_registry.py) не меняются от админки: на них опираются комитет,
 встречи и проверки. Справочник управляет группировкой, подписями и воронкой.

1. СХЕМА БД (полный DDL — status_admin.py, константа DDL)
 status_groups
   id INTEGER PK · name TEXT NOT NULL (1–120, уникально без учёта регистра)
   slug TEXT UNIQUE (латиница, цифры, дефис; 2–48) · description TEXT (≤600)
   color '#RRGGBB' (CHECK) · icon (check, gear, clock, shield, ban, filter, users,
   alert, mail, circle) · sort_order INT · is_active 0/1 (показ в дашбордах)
   is_system 0/1 (нельзя удалить) · funnel_role delivered|loss|neutral
   aggregation sum|share|avg · created_at · updated_at (UTC ISO)
 status_codes
   id INTEGER PK · code INTEGER UNIQUE, CHECK −99999…99999999 (−1 допустим)
   description TEXT NOT NULL (1–600) · group_id FK → status_groups ON DELETE RESTRICT
   alias TEXT NULL (1–80, подпись на графиках) · sort_order · is_active · is_system
   created_at · updated_at
 status_dashboard_settings (key, value): unassigned_mode group|hide, drill_down,
   default_aggregation, revision (растёт при каждом изменении), schema_version.
 status_audit: журнал изменений (кто/роль, что, когда, детали), последние 500.
 Связи и правила: 1 группа → N кодов. Группу с кодами SQLite удалить не даст
 (RESTRICT); API при удалении обычной группы переносит её коды в «Без группы»
 или в выбранную группу. Системные группы и коды (исходный справочник) не
 удаляются; их можно скрыть, переименовать, перекрасить, переставить; номер
 системного кода не меняется (он приходит из выгрузки). Оптимистичная блокировка:
 PATCH с expected_updated_at вернёт 409, если запись уже изменили.
 Начальное заполнение — 5 групп из промта + системная «Без группы».

2. API (все ответы JSON; ошибка: {"error": "...", "fields": {"поле": "текст"}})
 GET    /api/status-groups                      200 {items[], role, settings}
 POST   /api/status-groups                      201 группа · 400 поля · 409 имя/slug занят
 PATCH  /api/status-groups/:id                  200 · 404 · 409 (системный slug, версия)
 DELETE /api/status-groups/:id  {move_to?}      200 {moved, move_to} · 409 системная
 PATCH  /api/status-groups/reorder  {ids[]}     200 · 409 если список устарел
 GET    /api/status-codes?group_id=&q=&page=&page_size=   200 {items, total, page, pages}
        (page_size до 500; q ищет по коду, описанию и алиасу без учёта регистра)
 POST   /api/status-codes                       201 · 400 · 409 код уже есть
 PATCH  /api/status-codes/:id                   200 · 404 · 409
 PATCH  /api/status-codes/:id/move  {group_id}  200 · 400 нет группы
 DELETE /api/status-codes/:id                   200 · 409 системный
 PATCH  /api/status-codes/reorder {group_id, ids[]}   200 · 409
 GET    /api/status-tree[?include_inactive=1]   дерево «группы → коды» для легенд и
        фильтров, по sort_order, с revision и ttl (без include_inactive — с кэшем)
 GET/PATCH /api/status-settings                 режим «Без группы», drill-down, агрегация
 GET    /api/status-audit?limit=30              журнал изменений
 GET    /api/status-config/export?format=json|csv
 POST   /api/status-config/import {format: json|csv, content, mode: merge|replace,
        dry_run: true|false}                    план изменений; при ошибках в файле
        применение запрещено (400); ничего не удаляется, replace только выключает
 GET    /api/analytics/status-breakdown?group_by=group|code&grain=total|month|day
        &date_from=ГГГГ-ММ-ДД&date_to=…&ids=1427,1428
        события по группам/кодам пуш+СМС: сумма, доля от событий, среднее в день;
        unknown — коды из выгрузки, которых нет в справочнике.
 Прочее: 403 — роль без прав; 404 — нет адреса/записи; 405 — не тот метод;
 413 — файл импорта больше 4 МБ. Запросы на изменение принимаются только со
 страницы локального проекта (проверка Origin).

 - Группы: перетаскивание (и ↑↓), переключатель «в дашбордах», счётчик кодов,
   ◆ — системная. Код можно перетащить из таблицы на группу — он перенесётся.
 - Таблица кодов: перетаскивание внутри группы, ↑↓, переключатель активности,
   ✎ изменить, ⇄ перенести (модалка с подсказкой, как код посчитается), 🗑 удалить
   (для системных недоступно, с объяснением). Поиск — по всем группам, страницы по 100.
 - Формы: обязательные поля, целое число кода (−1 допустим), ошибки сервера
   показываются под полями (например, «Код уже используется»).
 - Превью легенды — как в дашборде: порядок, цвет, иконка; группа раскрывается до
   кодов с алиасами. «На ваших данных» — доли групп по текущей выгрузке и коды,
   которых нет в справочнике (кнопка «Добавить» заполняет форму).
 - Состояния: скелетон при загрузке, пустая группа / пустой поиск, ошибка с
   «Повторить», уведомления об успехе и ошибке (toast, role=status).
 - Роли (.local-data/access.json → {"statusAdmin": "admin|analyst|viewer"}, по
   умолчанию admin): admin — всё; analyst — только просмотр (кнопки скрыты, сервер
   отвечает 403 на изменения); viewer — админка закрыта (403), дашборды и
   /api/status-tree доступны.

4. КАК АДМИНКА ВЛИЯЕТ НА ДАШБОРДЫ
 - Воронка диалога (кнопка «Воронка»): шаги между событиями и отправками — активные
   группы с ролью «отсечение» в порядке sort_order, с их названиями и цветами.
   Неотправленная часть событий каждого status_det относится к группе своего кода.
 - Drill-down: клик по группе в воронке открывает её коды (алиас, события, доля);
   таблицы по периодам и опросам сортируются по этой группе. Выключается настройкой.
 - Коды без группы, выключенные коды и выключенные группы в расчётах попадают в
   «Без группы», чтобы сумма шагов всегда сходилась с событиями; режим «Скрывать»
   убирает «Без группы» из легенды и фильтров.
 - Алиасы — подписи кодов на графиках и в drill-down; без алиаса — описание.
 - Кэш дерева: 5 минут в памяти сервера, сбрасывается сразу при любом изменении;
   номер версии справочника виден в «Как рассчитано» воронки.
 - Коды выгрузки, которых нет в справочнике, подсвечиваются в воронке и в админке.

6. ТЕСТЫ И EDGE-CASES (покрыто в status_admin_tests.py, 20 тестов)
 [x] уникальность кода при создании и редактировании (409)
 [x] отрицательные коды (−1, «−1» с типографским минусом) хранятся и находятся
 [x] запрет удаления системных групп и кодов; номер системного кода не меняется
 [x] перенос кода между группами; перенос в несуществующую группу — ошибка
 [x] сортировка групп и кодов; устаревший список при сортировке — 409
 [x] удаление группы переносит коды в «Без группы»
 [x] валидация: пустые поля, длина, цвет, не число, дробь, true вместо числа
 [x] уникальность названия группы без учёта регистра (кириллица)
 [x] оптимистичная блокировка (expected_updated_at → 409)
 [x] инвалидация кэша и рост revision после изменения
 [x] скрытые группы и режим «Без группы: скрывать» в дереве
 [x] роли: analyst — только чтение, viewer — нет доступа к админке
 [x] импорт: dry-run ничего не пишет; CSV и JSON; дубли и ошибки блокируют
     применение; replace выключает отсутствующие коды; экспорт → импорт = 0 изменений
 [x] разбивка: сумма по группам = события; неизвестные коды; выключенная группа → «Без группы»
 [x] HTTP-диспетчер: 201, 404, 405, CSV-экспорт, пагинация
