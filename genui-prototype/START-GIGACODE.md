# Запусти GEN UI мониторинг по этой инструкции

Это инструкция на выполнение для GigaCode CLI. Пользователь разрешает проверить
проект, настроить подключение к установленной CLI, сделать один короткий реальный
запрос к модели, запустить локальный сервер и открыть браузер.

1. Найди корень распакованного проекта: рядом должны находиться
   `bootstrap_project.py`, `launch_local.py` и папка `date`.
   Архив содержит вложенную папку `genui-prototype`: если ты в родительской
   папке, перейди в неё. Не копируй CSV между папками молча.
2. Найди Python 3.10+: проверь `python --version`; на macOS/Linux при отсутствии
   такой команды проверь `python3 --version`, на Windows — `py -3 --version`.
   Используй найденную команду далее. Если подходящего Python нет, объясни,
   что требуется установить Python 3.10+, и остановись. Не устанавливай ПО сам.
3. Выполни из корня проекта:

   ```bash
   python bootstrap_project.py
   ```

   Замени `python` на проверенный `python3` или `py -3`, если требуется.
   Дай команде до 10 минут: она проверяет реальные CSV, создаёт конфигурацию CLI
   только при её отсутствии, делает один настоящий запрос на синтетических
   данных, запускает сервер отдельным процессом и открывает сайт. Сервер
   продолжит работу после завершения команды. Вызов модели может расходовать квоту.
4. При успешном выходе прочитай `.local-data/startup-result.json` и проверь
   указанный адрес `/api/health` вместо `/genui/`: сервер должен ответить,
   версия должна совпасть с `app_version.py`. Браузер открывает ТОЛЬКО скрипт.
   Не выполняй open/start/xdg-open, webbrowser.open и не открывай URL через
   браузерный инструмент после успешного запуска — это создаёт вторую вкладку.
   browserOpened=true означает, что запрос открытия уже отправлен; задержка
   появления окна не является основанием открыть его ещё раз.
   Если browserOpened=false или поле отсутствует, просто дай пользователю
   адрес url и объясни, что его можно открыть вручную. Не открывай сам.
   Не считай порт 8015 гарантированным: он может быть занят.
5. Сообщи пользователю адрес сайта, результат проверки CSV и короткого запроса
   к модели. Уточни, что тест подключения не доказывает работоспособность любой
   генерируемой визуализации. Для первого обычного графика используй режим
   «GigaCode CLI» с отключённой опцией «Создать новую визуализацию».

## Если что-то не получилось

- Код выхода 2 означает, что сервер ещё запускается, а не упал. Не запускай
  launch_local.py/start_local.py вручную и не вызывай модель повторно. Повтори
  bootstrap_project.py: он дождётся уже запускающегося сервера.
- При другом ненулевом коде выхода останови запуск и назови этап и ошибку.
- Не заменяй реальную модель mock-ответом, не обходи проверку JSON и не повышай
  тайм-ауты без объяснения. Не сообщай «всё работает» по одному открытому сайту.
- Если требуется вход в GigaCode, попроси пользователя выполнить вход самому
  в терминале. Не проси присылать токены и не записывай их в проект.
- Для подробного разбора модели предложи `python diagnose_project.py --probe-model`.
  Не выполняй повторные платные вызовы без необходимости: сначала покажи ошибку.
- Если текущая сессия CLI находится в режиме только планирования и не может
  выполнять команды, объясни пользователю, что для запуска нужен режим выполнения.
  Не меняй глобальные разрешения CLI автоматически.

## Ограничения задачи запуска

Не редактируй исходный код, CSV, справочники, пользовательскую конфигурацию,
историю и тайм-ауты ради запуска. Не удаляй `.local-data` и не очищай `baseline.json`.
Не убивай процессы по номеру порта и не запускай второй сервер поверх существующего.
Готовый скрипт сам проверяет идентичность сервера и повторно использует его.
Никаких git push, установки пакетов или изменений системы для этой задачи не требуется.
